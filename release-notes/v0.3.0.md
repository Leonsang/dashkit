# dashkit v0.3.0

## New: `pbi-sdd`, a spec-driven workflow for Power BI

dashkit's first bundle of its own — one skill, embedded in the binary, installed into every tool.
It turns Power BI work into written, reviewable steps kept in `sdd/` next to the `.pbip`:

- **`/pbi-sdd survey`** — a *levantamiento* of a report that already exists, locally or published.
  A bundled Node script inventories pages, visuals, measures, relationships and data sources, and
  cross-references them to flag what is easy to miss: measures used by nothing (not visuals, filters,
  bookmarks, or other measures), broken field references, local file paths that break refresh in the
  service, Auto date/time tables, and measures without descriptions, formats or folders. The agent
  writes the survey from that evidence, with findings ranked and questions for the owner.
- **`/pbi-sdd new`** — starts a report by running Microsoft's `powerbi-report-planning` rounds and
  ends in a spec with checkable acceptance criteria.
- **`spec → tasks → build → verify`** — no task before the user approves the spec; tasks one at a
  time, each with its own check; verification that shows evidence for every criterion.

It adds no craft of its own: it decides when Microsoft's and data-goblin's skills are used and what
gets written down. One skill, with each phase in a reference loaded on demand, so it costs almost no
context. The wizard preselects it with Power BI authoring.
