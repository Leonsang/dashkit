# dashkit v0.2.2

Everything here came out of installing v0.2.1 on a real Power BI project and watching it run.

## Fixed

- **Each command is shown once.** Every command used to appear twice — as a log line and again in
  the confirmation. Now the command is printed, and the question is just `proceed? [y/N]`.
- **Saying no is a decision, not an error.** Declining a prerequisite prints
  `skipped Azure CLI: you declined` instead of `! could not install …`; declining a plugin skips that
  one step and the rest of the run carries on, instead of aborting.
- **A plugin is approved once, for both of its commands.** Declaring the marketplace and installing
  the plugin are confirmed together, so a "no" can't leave a marketplace declared with nothing
  installed from it.
- **`--dry-run` and the wizard's review list every command** — both commands of each plugin install,
  not a one-line summary. The review screen approves everything at once, so it has to show all of it.
- **After installing a prerequisite, dashkit reloads PATH, checks again, and tells you to restart
  tools that were already open.** On Windows, winget often adds a package to the user PATH rather than
  linking it somewhere already on it; a running Claude Code keeps the old PATH, and data-goblin's
  hooks would run without `jq` and silently validate nothing until it was restarted.
- The wizard no longer reports "-1 file changes" when a step runs two commands.
- `dashkit update` skips — and explains — a recorded bundle that upstream has retired, instead of
  stopping at the first one.

## Updated

- **Microsoft's skills-for-fabric pinned to v0.3.16** (was v0.3.11). Upstream retired the
  `fabric-authoring`, `fabric-consumption` and `fabric-operations` bundles — every skill they carried
  is in `fabric-skills` — merged skills per Fabric item (`spark-cli`, `sqldw-cli`, …) and removed
  `check-updates`. dashkit now offers `powerbi-authoring` and `fabric-skills`.
- **MCP servers that authenticate with `headersHelper`** — v0.3.16's remote Fabric servers run
  `az account get-access-token` for a token — are registered only in Claude Code, which runs that
  command. Other tools get them written to `.dashkit/<bundle>/MCP-SERVERS.md` with the command to use,
  instead of a registration that would fail on every call. Previously the field was dropped silently.

## Docs

- The docs now say where a bundle's version comes from: copied bundles use the pinned tag; installs
  through Claude Code's or Copilot CLI's plugin manager get whatever the marketplace publishes now.
