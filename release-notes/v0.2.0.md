# dashkit v0.2.0

The first release as **dashkit** (previously fabkit). This one is about installing *less*, and
installing it *properly*.

## Breaking

- **Renamed from fabkit to dashkit.** The binary, the `~/.dashkit` directory, the `DASHKIT_*`
  environment variables, the `.dashkit/` vendor folder and the `<!-- dashkit:… -->` markers all
  changed. There is no automatic migration: run `fabkit uninstall` with v0.1.0 first if you used it.
- **Installs are project-scoped by default.** Every installed skill competes for the agent's attention
  in every session its scope covers, so `--scope project` is now the default and `--scope global` is
  the deliberate choice.

## New

- **data-goblin bundles**: `goblin-pbip`, `goblin-pbi-desktop`, `goblin-semantic-models`,
  `goblin-reports` and `goblin-tabular-editor`, from Kurt Buhler's
  [power-bi-agentic-development](https://github.com/data-goblin/power-bi-agentic-development).
  They install through Claude Code's or Copilot CLI's own plugin manager — dashkit never copies them —
  and bring hooks that validate PBIR, TMDL and report binding after every edit.
- **Plugins are uninstallable.** Plugins dashkit asked a host to install are recorded and handed back
  to that host on `dashkit uninstall`; a declined or failed removal stays on record.
- **Context warnings**: the wizard and the CLI warn when a selection is large for its scope, and
  `--bundle all` asks for confirmation.
- **Required vs optional prerequisites**: `dashkit doctor` fails only when something *required* is
  missing, and says which is which.
- `dashkit list` shows each bundle's author, hooks and how it installs.
- New docs: [targets](../docs/targets.md), [safety](../docs/safety.md), [bundles](../docs/bundles.md),
  [attributions](../ATTRIBUTIONS.md).

## Fixed

- Commands run by the wizard no longer write over its screen.
- Python detection no longer mistakes the Windows Store `python3` alias for an installed Python.
- `--dry-run` now shows which bundle/tool combinations will be skipped, and why.
- Claude Code and Copilot CLI plugin installs respect the chosen scope instead of always installing
  for the user.

## Deliberately not done

- **pbir-cli is not installed automatically.** Its licence is proprietary and non-commercial, and
  forbids use inside other software without consent. `dashkit doctor` reports it and explains.

## Known

- After uninstalling a project-scoped Claude Code plugin, Claude Code leaves
  `.claude/settings.json` holding empty `enabledPlugins` and `extraKnownMarketplaces` objects. The
  plugin and the marketplace declaration dashkit added are both gone; the empty file is Claude's.
